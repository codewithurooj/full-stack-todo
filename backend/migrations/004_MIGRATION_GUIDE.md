## Detailed Schema Changes

### 1. audit_logs Table

**Purpose:** Store comprehensive audit trail of all task operations consumed from Kafka `task-events` topic.

**Columns:**

| Column | Type | Nullable | Default | Purpose |
|--------|------|----------|---------|---------|
| id | SERIAL | NO | nextval(...) | Primary key |
| event_id | UUID | NO | - | Idempotency key from Kafka event (unique) |
| timestamp | TIMESTAMPTZ | NO | - | Original event timestamp |
| user_id | INTEGER | NO | - | User who performed operation |
| task_id | INTEGER | YES | - | Task affected (NULL for non-task events) |
| operation_type | VARCHAR(50) | NO | - | Event type (task.created, etc.) |
| event_payload | JSONB | NO | - | Full event JSON for forensics |
| system_generated | BOOLEAN | YES | FALSE | TRUE if auto-generated by service |
| created_at | TIMESTAMPTZ | YES | NOW() | Database insertion timestamp |

**Indexes:**

| Index Name | Type | Columns | Notes |
|------------|------|---------|-------|
| audit_logs_pkey | PRIMARY KEY | id | Clustered index |
| audit_logs_event_id_key | UNIQUE | event_id | Idempotency enforcement |
| idx_audit_logs_task_id | B-tree (partial) | task_id | WHERE task_id IS NOT NULL |
| idx_audit_logs_user_id | B-tree | user_id | Fast user lookups |
| idx_audit_logs_timestamp | B-tree | timestamp DESC | Recent-first sorting |
| idx_audit_logs_operation_type | B-tree | operation_type | Filter by event type |

**Foreign Keys:**
- `fk_audit_logs_user_id` → `users(id)` ON DELETE CASCADE
- `fk_audit_logs_task_id` → `tasks(id)` ON DELETE SET NULL

**Check Constraints:**
- `chk_audit_logs_operation_type`: Ensures operation_type IN ('task.created', 'task.updated', 'task.deleted', 'task.completed')
- `chk_audit_logs_timestamp`: Prevents far-future timestamps (max 1 hour in future)

**Retention Policy:**
```sql
-- Clean up old audit logs (run daily via cron job)
DELETE FROM audit_logs WHERE created_at < NOW() - INTERVAL '90 days';
```

### 2. notification_subscriptions Table

**Purpose:** Store Web Push notification subscriptions for browser notifications.

**Columns:**

| Column | Type | Nullable | Default | Purpose |
|--------|------|----------|---------|---------|
| id | SERIAL | NO | nextval(...) | Primary key |
| user_id | INTEGER | NO | - | User who granted permission |
| endpoint | TEXT | NO | - | Push service endpoint URL |
| p256dh | TEXT | NO | - | Public key for encryption (VAPID) |
| auth | TEXT | NO | - | Auth secret for verification |
| created_at | TIMESTAMPTZ | YES | NOW() | Subscription creation timestamp |
| updated_at | TIMESTAMPTZ | YES | NOW() | Last subscription update |

**Indexes:**

| Index Name | Type | Columns | Notes |
|------------|------|---------|-------|
| notification_subscriptions_pkey | PRIMARY KEY | id | Clustered index |
| notification_subscriptions_user_id_endpoint_key | UNIQUE | (user_id, endpoint) | Prevent duplicates |
| idx_notification_subs_user_id | B-tree | user_id | Fast user lookups |

**Foreign Keys:**
- `fk_notification_subs_user_id` → `users(id)` ON DELETE CASCADE

**Note:** Alternative approach is to store subscriptions in frontend localStorage (simpler for MVP).

---

### 3. Idempotency Constraint on tasks Table

**Purpose:** Prevent duplicate recurring task instances from being created by Recurring Task Service.

**Index:**
```sql
CREATE UNIQUE INDEX idx_recurring_instance_dedup
    ON tasks(parent_task_id, due_date)
    WHERE parent_task_id IS NOT NULL;
```

**Strategy:** Unique constraint on (parent_task_id, due_date) for recurring instances only (partial index).

**Benefit:** Database-level enforcement of idempotency for recurring task creation.

## SQLModel Updates

### New Models Created

#### 1. AuditLog Model

**File:** `backend/app/models/audit_log.py`

```python
from sqlmodel import SQLModel, Field, Column
from sqlalchemy import JSONB
from datetime import datetime
from typing import Optional
from uuid import UUID

class AuditLogBase(SQLModel):
    event_id: UUID = Field(unique=True, nullable=False)
    timestamp: datetime = Field(nullable=False)
    user_id: int = Field(foreign_key="users.id", nullable=False)
    task_id: Optional[int] = Field(default=None, foreign_key="tasks.id")
    operation_type: str = Field(max_length=50, nullable=False)
    event_payload: dict = Field(sa_column=Column(JSONB, nullable=False))
    system_generated: bool = Field(default=False)

class AuditLog(AuditLogBase, table=True):
    __tablename__ = "audit_logs"
    id: Optional[int] = Field(default=None, primary_key=True)
    created_at: datetime = Field(default_factory=datetime.utcnow)

class AuditLogCreate(AuditLogBase):
    pass

class AuditLogRead(AuditLogBase):
    id: int
    created_at: datetime

VALID_OPERATION_TYPES = {
    "task.created", "task.updated", "task.deleted", "task.completed"
}
```

#### 2. NotificationSubscription Model

```python
from sqlmodel import SQLModel, Field
from datetime import datetime
from typing import Optional

class NotificationSubscriptionBase(SQLModel):
    user_id: int = Field(foreign_key="users.id", nullable=False)
    endpoint: str = Field(nullable=False)

class NotificationSubscription(NotificationSubscriptionBase, table=True):
    __tablename__ = "notification_subscriptions"
    id: Optional[int] = Field(default=None, primary_key=True)
    created_at: datetime = Field(default_factory=datetime.utcnow)

    p256dh: Optional[str] = None
    auth: Optional[str] = None
    updated_at: datetime = Field(default_factory=datetime.utcnow)

class NotificationSubscriptionRead(NotificationSubscriptionBase):
    id: int
    created_at: datetime
    updated_at: datetime
```

## Notes

### Important Considerations

1. **Audit Log Retention:** Set up a cron job to clean up old audit logs (90 days recommended):
   ```sql
   DELETE FROM audit_logs WHERE created_at < NOW() - INTERVAL '90 days';
   ```

2. **Notification Subscriptions:** Consider using frontend localStorage for MVP instead of database storage (simpler).

3. **Idempotency:** The unique constraint on tasks table prevents duplicate recurring instances at the database level (fail-safe).

4. **Event Sourcing:** Audit logs store full event payloads (JSONB) for forensic analysis and debugging.

5. **Performance:** Partial index on task_id (WHERE task_id IS NOT NULL) saves space and improves query performance.

### Future Enhancements

- Add GIN index on event_payload for full-text search (optional)
- Partition audit_logs table by month for better performance
- Add materialized view for audit log analytics
- Implement automatic archival of old audit logs
